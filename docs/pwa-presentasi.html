01 · Kalimat utama

Apa itu PWA?

Hafalkan satu kalimat ini, lalu jelaskan dengan analogi di bawah.

PWA itu website biasa yang dikasih "identitas aplikasi" dan "otak cache", sehingga bisa dipasang di HP Android, dibuka fullscreen tanpa address bar, dan tetap jalan walau internet mati — tanpa harus bikin aplikasi native atau Flutter. PWA bukan aplikasi baru, bukan framework baru, bukan bahasa baru. Ini kemampuan tambahan pada website yang sudah ada.
02 · Analogi

Cara paling mudah menjelaskannya

Pakai perumpamaan brosur — ampuh untuk audiens non-teknis.

Website biasa = brosur di kantor

Tiap mau baca harus datang lagi ke kantor (request ke server). Kalau kantor tutup / internet mati, tidak bisa baca.

→

PWA = brosur yang difotokopi ke tas

Sekali diambil lalu disimpan (cache), bisa dibaca kapan saja. Dikasih cover & label nama (manifest) supaya bisa ditaruh di rak depan = home screen.

Service worker = asisten yang berdiri di antara HP dan server. Ia yang memutuskan: ambil dari "tas" dulu, atau telepon server.

03 · Tiga pilar

Apa saja yang ditambahkan?

Hanya 3 hal wajib + ikon. Semua sudah ada di project.

PILAR 1

HTTPS / Secure context

Syarat keamanan: service worker hanya boleh jalan di HTTPS. localhost dikecualikan untuk development. Deploy ke Netlify/Vercel = HTTPS otomatis.

PILAR 2

Web App Manifest

"KTP aplikasi": nama, ikon, warna tema, start_url, dan display: standalone. File manifest.webmanifest di-generate dari vite.config.js.

PILAR 3

Service Worker

Script background: install → precache → intercept request → update. Di-generate otomatis oleh Workbox menjadi sw.js.

04 · Alur kerja

Apa yang terjadi saat user membuka Parakarsa?

Urutan ini yang paling sering ditanya PIC.

  1. User buka URL HTTPS di Chrome.
  2. index.html diunduh → React + Vite jalan seperti biasa.
  3. src/pwa.js mendaftarkan sw.js ke browser.
  4. SW install: semua aset build disimpan ke Cache Storage (app shell, 35 file ±3,6 MB).
  5. SW activate → langsung mengontrol tab yang sedang dibuka.
  6. Browser baca manifest + cek syarat → memicu beforeinstallprompt.
  7. User klik "Pasang" → Android bikin ikon + splash screen.
  8. Buka dari ikon → standalone, tanpa address bar, status bar ikut warna brand.
  9. Internet mati → SW jawab dari cache; /main dll tidak 404.
  10. Ada deploy baru → toast "Versi baru tersedia" → klik Perbarui.

06 · Batasan

Yang bisa & yang tidak (jangan over-promise)

✅ Bisa

  • Dipasang di Android, fullscreen tanpa address bar
  • Ikon, splash screen, shortcut (Dashboard, Kartu Anggota)
  • Offline untuk seluruh halaman & aset statis — sudah diuji
  • Update otomatis + notifikasi versi baru
  • Desain mobile existing tidak berubah
  • Font Google ikut ter-cache

⚠️ Terbatas

  • iOS: Add to Home Screen manual, tidak ada install prompt
  • Wajib HTTPS (kecuali localhost)
  • Akses hardware native tidak selengkap aplikasi native
  • Data dari API server tetap butuh internet
  • Tidak otomatis muncul di Play Store (perlu TWA)
07 · Siap ditanya

Prediksi pertanyaan PIC

Klik untuk membuka jawaban singkatnya.

"Ini aplikasi atau website?"

Website yang bisa dipasang seperti aplikasi. Satu codebase, satu deploy — bukan dua aplikasi.

"Kenapa tidak jadi Flutter?"

Untuk kebutuhan "buka di Android", PWA cukup. Flutter baru perlu kalau butuh fitur native penuh atau aplikasi mandiri di Play Store.

"Kalau internet mati, datanya hilang?"

Tampilan & data lokal aman. Data yang bersumber dari server/API baru muncul saat online — PWA menjamin tampilan & aset, bukan sinkronisasi realtime.

"Bisa masuk Play Store?"

Bisa. Dibungkus Trusted Web Activity (PWABuilder / Bubblewrap) jadi APK. Kode web tetap sama, hanya dibungkus.

"iPhone bisa?"

Bisa dibuka dan ditambahkan ke Home Screen, tetapi alur install tidak semulus Android dan push notification terbatas.

"Update aplikasinya bagaimana?"

Tinggal deploy. User mendapat toast "Versi baru tersedia", klik Perbarui, selesai — tanpa uninstall, tanpa review toko aplikasi.

"Apakah desain mobile-nya berubah?"

Tidak. Seluruh folder src/mobile/ tetap dipakai apa adanya. Yang berubah hanya config, ikon, dan 2 file komponen baru.
